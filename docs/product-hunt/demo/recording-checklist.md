# Demo recording checklist

## Prepare

- [ ] Use the exact public release candidate from a clean account.
- [ ] Set SideRefresh to English and use the intended public appearance.
- [ ] Use `Examples/SideRefreshSampleApp/SideRefreshSample.xcodeproj`, scheme
      `SideRefreshSample`, and product `SideRefresh Sample`; do not use a private
      project.
- [ ] Give the physical device a neutral public name and hide unrelated devices.
- [ ] Complete Xcode sign-in, Personal Team selection, pairing, trust, Developer
      Mode, and one verified installation before recording.
- [ ] Close notifications, personal apps, Finder windows, terminals, and account
      settings; disable notification previews.
- [ ] Record 1920×1080 or higher at 30 fps with a readable cursor.

## Never reveal

- Apple Account email, Team ID, certificate names, provisioning profile data;
- full paths or repository names tied to private work;
- UDID, serial, hardware identifiers, IP addresses, Tailnet names or addresses;
- password prompts, tokens, signing keys, private logs, notifications;
- other projects, devices, users, browser history, or desktop contents.

## Accuracy

- [ ] Show the public app, not a design prototype.
- [ ] Show a real refresh result; do not replace failure with a staged success.
- [ ] Label condensed build time on screen.
- [ ] Do not call the profile permanent or say Xcode is unnecessary.
- [ ] Do not imply third-party IPA, fleet, or verified cellular installation.
- [ ] Keep Tailscale out of the core demo while it remains experimental.

## Final review

- [ ] Watch once at 100%, once frame-by-frame, and once without audio.
- [ ] Check English captions, contrast, cursor visibility, and mobile crop.
- [ ] Confirm narration, UI, README, release notes, and gallery agree.
- [ ] Add the Apple trademark and independent-project notice in the description.
- [ ] Upload public or Unlisted; test the full YouTube URL while logged out.
