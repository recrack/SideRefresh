# SideRefresh 사용 설명서

[English](MANUAL.md) | [한국어](MANUAL.ko.md)

SideRefresh는 본인이 소유한 iOS 앱 한 개를 무료 Personal Team 서명이
만료되기 전에 다시 빌드·서명·설치해 iPhone 한 대에서 계속 사용할 수 있게
합니다.

타인의 IPA 설치, Apple 서명 우회, 프로파일 영구화, Apple 또는 Tailscale
로그인 대행, Xcode 없는 사용은 지원하지 않습니다.

## SideRefresh를 열기 전에

1. Xcode를 설치하고 **Xcode → Settings → Accounts**에서 Apple Account를
   추가합니다.
2. 앱 프로젝트의 iOS Application Target에서 자동 서명을 켜고 Personal
   Team을 선택합니다.
3. iPhone을 연결하고 잠금을 해제한 뒤 Mac 신뢰와 Developer Mode를
   승인합니다.
4. **Xcode → Window → Devices and Simulators**에서 iPhone을 페어링합니다.
5. 실행 대상을 그 iPhone으로 정하고 **Product → Run**을 한 번 실행합니다.

이 첫 실행에서 Apple이 로컬 개발 서명 자산을 만들고, SideRefresh가 대신할
수 없는 신뢰 절차가 완료됩니다. Xcode에 계정이나 프로비저닝 프로파일이
없다는 오류가 보이면 [Personal Team 준비](PERSONAL-TEAM-SETUP.ko.md)를 먼저
따르세요.

## 1. 내 앱 선택

Simple 홈에서 **설정**을 열고 **앱 선택**을 누릅니다.

앱 선택 화면은 별도 팝업을 겹쳐 띄우지 않고 같은 설정 창의 내용을
교체합니다. 검색 위치는 기본적으로 한 줄 상태만 표시하며, 경로·개인정보
안내·접근 문제를 확인할 때만 펼칩니다. 펼친 뒤에도 헤더와 아래의 고정 확정
영역은 유지됩니다.

`.xcworkspace` 또는 `.xcodeproj` 한 개를 고릅니다. CocoaPods처럼
워크스페이스 설정이 필요한 프로젝트는 워크스페이스를 우선합니다. 확정하기
전에 다음을 확인합니다.

- 앱 이름과 아이콘
- Bundle ID와 앱 버전
- iOS Application Target과 Scheme
- Personal Team
- 정확한 Xcode 파일 경로

SideRefresh는 검색을 위해 Xcode 프로젝트 메타데이터와 앱 아이콘을 읽지만
소스 코드를 업로드하거나 수정하지 않습니다. 목록에서 강조된 항목은 아래
고정 영역에서 확정하기 전까지 제안일 뿐입니다.

## 2. iPhone 한 대 선택

**iPhone 선택**을 누릅니다. SideRefresh는 이 동작을 실행했을 때만 Xcode가
알고 있는 기기 목록을 읽습니다.

후보에는 iPhone 이름, 확인 가능한 모델, iOS 버전과 짧은 식별자 끝자리가
표시됩니다. 한 대를 고르고 **선택한 iPhone 사용**을 누릅니다. 네트워크
주소가 달라져도 실제 설치 대상은 CoreDevice UDID로 유지됩니다.

기기가 보이지 않으면 iPhone 잠금을 해제하고 Xcode 페어링부터 확인하세요.

## 3. 연결 준비 방식 선택

Xcode/CoreDevice 카드는 항상 표시됩니다. **Xcode에서 iPhone 확인**은 현재
Xcode 기기 목록에 선택한 iPhone이 있는지 확인합니다.

### 추가 주소 없음

USB 또는 Xcode가 이미 사용할 수 있는 네트워크 경로에 사용합니다. 실제
전송 경로는 Xcode가 선택합니다.

### Tailscale · 실험적

원격 주소를 준비하는 선택 기능입니다. Mac에 실행 가능한 Tailscale이
있어야 하고 iPhone에도 Tailscale이 설치되어 같은 Tailnet에 로그인되어야
합니다.

1. **Tailscale · 실험적**을 선택합니다.
2. 사용할 수 없다고 나오면 Tailscale을 설치하거나 열고 다시 확인합니다.
3. **iPhone 찾기**를 누르고 구분 가능한 기기를 고릅니다. 기기 이름(DNS 이름은
   대체값), 우선 IP 주소와 짧은 안정적 Node ID가 함께 표시됩니다.
4. **Tailscale 주소 확인 완료** 후에도 **Xcode에서 iPhone 확인**을 별도로
   실행합니다.

Tailscale 온라인은 Xcode 연결 성공을 뜻하지 않습니다. CoreDevice UDID,
최초 페어링, 신뢰, Developer Mode, Apple 서명을 대신하지도 않습니다. 순수
셀룰러 Tailnet을 통한 실제 CoreDevice 설치는 아직 공개 지원 범위로
검증되지 않았습니다.

### 직접 IP/DNS

직접 주소는 문제 해결용 고급 설정에 있습니다. Xcode에서 먼저 **Connect via
IP Address**를 실행해야 할 수 있습니다.

## 4. 설정 저장

설정 창 아래에는 고정된 저장 영역이 있습니다.

- **설정 미완료:** 저장이 비활성화되고 다음으로 확인할 설정 영역이 표시됩니다.
- **저장 필요:** **설정 저장** 또는 **변경사항 저장**으로 현재 초안을
  적용합니다.
- **저장됨:** 현재 앱, iPhone과 연결 방식이 이미 활성 상태입니다.

Tailscale을 선택했다면 Mac의 실행 파일과 Tailnet iPhone 한 대가 준비될
때까지 저장할 수 없습니다. 선택 화면을 확정하지 않고 닫으면 이전 초안이
유지됩니다.

## 5. 첫 갱신 확인

**내 앱**으로 돌아가 **지금 갱신**을 실행하고 앱과 iPhone을 확인합니다.
실제 갱신은 다음 순서로 동작합니다.

1. 저장된 대상과 연결 준비 상태 확인
2. 선택한 Personal Team으로 Xcode 빌드
3. 빌드 결과의 Bundle ID 검증
4. 포함된 서명 만료일 확인
5. CoreDevice를 통한 설치
6. 필요한 증거가 있을 때만 성공 기록

진단 로그에서 Xcode와 CoreDevice 원문을 확인할 수 있습니다. 프로세스 종료
코드만 성공하고 설치·만료 증거가 없으면 검증된 갱신으로 표시하지 않습니다.

## 6. 자동 갱신 켜기

무료 Personal Team에는 144시간(6일) 간격을 권장합니다. 현재 앱 버전을
유지할지 갱신 때 다음 버전으로 올릴지도 선택합니다. 설정을 먼저 저장한 뒤
**자동 갱신**을 명시적으로 켭니다.

백그라운드 Agent는 짧게 실행됩니다. 갱신 시점에는 Mac이 깨어 있고,
프로젝트가 저장된 경로에 있으며, Xcode 서명이 동작하고, iPhone에 연결할 수
있어야 합니다.

## Simple 홈 읽기

고정된 왼쪽 사이드바는 **내 앱**을 선택한 상태로 열리고 **설정**, **도움말**,
**진단 로그**로 바로 이동할 수 있습니다. 메뉴를 선택하면 새 창을 열지 않고
같은 시작 창 안의 페이지만 바뀝니다. 상단 왼쪽에는 현재 앱, 오른쪽에는 작은
**마지막 검증** 시각이 표시됩니다. 스크롤하는 홈 본문은 다음 순서입니다.

1. 현재 갱신 상태와 최대 한 개의 다음 행동
2. 내 앱 → 빌드·서명·설치 → 내 iPhone 관계
3. 다음 갱신 가능 시각과 기록된 서명 만료
4. 현재 자동 갱신 방식과 연결 방식
5. 현재 진행 상황 또는 최근 결과

마지막 검증 기록은 과거 설치 증거이며 현재 연결 상태를 뜻하지 않습니다.
마우스를 올리거나 VoiceOver를 사용하면 이 설명과 기록된 만료일을 확인할 수
있습니다.

## 언어

Simple 홈, 최초 설정과 앱·iPhone 선택 화면에는 영어와 한국어가 포함됩니다.
**설정 → 언어**에서 **시스템 설정 따르기**, **한국어**, **English** 중 하나를
선택할 수 있습니다. 기본값은 macOS가 이 앱에 지정한 선호 언어를 따르며,
직접 고른 값은 다음 실행에도 유지됩니다. 사용자의 앱 이름, iPhone 이름,
Bundle ID, 버전, 주소, 식별자, 진단 로그와 Xcode 원문 오류는 번역하지 않고
그대로 표시합니다.

## 첫 릴리스 지원 범위

- 사용자가 소유한 앱 1개
- Xcode 프로젝트 또는 워크스페이스 1개
- 페어링된 실제 iPhone 1대
- Xcode와 Apple Account Personal Team이 있는 Mac

타인의 IPA 설치, 여러 앱·여러 iPhone 동시 관리, Xcode가 없는 사용자와 팀
단위 장비 관리는 첫 릴리스 범위 밖입니다.
